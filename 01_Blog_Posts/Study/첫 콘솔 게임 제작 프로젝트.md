## 2. 기획 목표 + 게임 플레이 흐름
#### 기획 의도
- Mr. Driller의 핵심 로직을 콘솔 엔진에서 구현하여, 최대한 원작과 비슷한 플레이를 느끼는 것이 목표
- 생성된 블록들 중 동일한 색상은 한 덩어리가 되는 것이 가장 핵심 특징
#### 게임 플레이 흐름
- 게임 실행
	→ 시작 메뉴
	→ 게임 시작
	→ 블록 생성 및 플레이어 배치
	→ 이동·드릴·산소 관리
	→ 카메라 스크롤과 추가 블록 생성
	→ 100m 도달 시 클리어, 또는 산소 소진·블록 압사 시 게임 오버
	→ 재시작 또는 메인 메뉴 이동
#### 핵심 게임 규칙
- 플레이어는 좌우 방향키로 이동한다.
- 위·아래 방향키로 드릴 방향을 전환한다.
- `Z` 키로 바라보는 방향의 블록을 파괴한다.
- 같은 색으로 연결된 블록은 한 번에 파괴된다.
- 일반 블록을 파괴하면 산소가 감소한다.
- 먼지 블록은 더 많은 산소를 소모한다.
- 산소 블록을 파괴하면 산소가 100%로 회복된다.
- 지지대를 잃은 블록 그룹은 아래로 낙하한다.
- 낙하하는 블록에 플레이어가 맞으면 게임 오버가 된다.
- 산소가 0이 되기 전에 목표 깊이 100m에 도달하면 클리어된다.

## 3. 개발 환경 및 엔진 구성
#### 프로젝트 구조
- ConsoleGameProject
	- CraftEngine
		- Engine
		- Level

		- Input

		- CollisionSystem
	-  MrDrillerGame
		- Game

		- Actor
		- Utils
#### 핵심 클래스
- DrillerGame
	- 전체 게임 상태를 관리
	- 시작, 플레이, 일시 정지 레벨 간 전환
	- 재시작 / 프로그램 종료 처리
-  DrillerLevel
	- 플레이어와 블록을 생성
	- 블록 검색 및 연결된 블록 그룹 탐색
	- 산소, 점수, 깊이 정보 관리
	- 블록 중력 및 압사 판정 처리
	- 카메라 스크롤, 월드 스트리밍
	- 자동 플레이 경로 탐색
- Player
	- 키 입력 처리, 이동 예정 위치 계산
	- 플레이어 중력 처리
	- 바라보는 방향, 드릴 처리 요청 관리
- Block
	- 블록의 종류, 색상 정보를 보관 및 출력
- UIActor
	- 깊이, 점수, 산소 게이지를 출력
	- 조작법, 게임 상태 출력
#### 엔진의 프레임당 처리 과정
- 입력 처리
	→ 레벨 초기화
	→ Tick
	→ 충돌 처리
	→ Draw
	→ 레벨 전환
	→ 액터 추가·삭제 반영
	→ 이전 프레임 상태 저장

## 4. 주요 구현 시스템
#### 동일 색상 블록 탐색
- 선택된 블록을 기준으로 상하좌우에 연결된 동일 색상의 블록을 반복 탐색하고, 이미 발견한 블록은 제외하여 하나의 블록 그룹을 구성하도록 했다.
- 반복문을 이용하여 너비 우선 탐색과 유사한 구조로 구현함.
#### 그룹 단위 블록 낙하
- 하나의 블록 그룹을 기준으로 그룹에 속한 모든 블록의 아래를 먼저 검사하고, 그룹 전체가 이동 가능할 때만 동을 분리해서 확장이 용이한 구조로 만들고 싶다. 또한 이번 프로젝트에서 중요하게 생각했던 블록 간 연결 탐색도 더 효율적으로 처리할 방법을 고민해 보고 싶다. 
#### 그럼에도 만족스러웠던 점
처음 프로젝트를 시작할 때 세웠던 목표는, 게임 시작부터 종료까지 흐름이 끊기지 않는 구조를 만들고, 그 안에 Mr. Driller의 핵심 기능을 최소한으로 구현하여 게임으로 성립시키는 것이었다.
그런 관점에서 보면 이번 프로젝트는 처음 세웠던 개인적인 목표를 충분히 달성한 프로젝트라고 생각한다.
짧은 기간 동안 촉박하게 진행한 프로젝트였지만, 발생한 문제를 정리하고 코드를 구성하는 방법을 배울 수 있었다고 생각한다. 또한 내가 부족했던 부분과 앞으로 개선할 수 있는 부분도 확인할 수 있었기 때문에 그만큼 좋은 경험이었던 것 같다.
